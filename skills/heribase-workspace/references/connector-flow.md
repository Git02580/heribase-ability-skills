# 统一添加入口与内部办理工具

用户统一使用“添加钱币”；网页 `add` 的同一个资料区接收一份或多份照片及表格，旧 `import` 链接转到同一页，不要求用户先选模式。以下命令是 Agent 内部办理工具，复用工作空间、任务包与现有 CLI 执行器，不构成另一个用户入口。正常用户操作只有给照片、开始识别、核对后加入收藏；内部任务键、revision、hash 和 commandId 由 Agent 管理。整批图片、目录及表格先按 `heribase-collection` 的全量配对方法处理，不把批量任务拆成多次单枚手选。自动配对建议、批量审核和选定范围识别均保留；已有任务中的资料直接复用，不再次建任务或重复归档。

## 网页上传后的默认流程

配对调整直接在添加页每枚钱币的“调整照片”中完成。正反面图片位支持从本批缩略图替换、交换及补图；没有完整的不同来源两面时不能保存。建议恰好包含两张不同图片且正反面唯一明确时，卡片提供“确认这组照片”，按当前展示版本就地保存；未知方向、重复角色或额外图片仍需“选择正反面”。宣传图与文档在“其他资料”中只查看。原 `#pairing?task=...&item=...` 链接兼容跳转到对应添加页并打开照片调整，不再进入旧审核步骤。

`POST /api/connector/photos` 接受 `taskKey`、`expectedRevision`、`localId`、`obverseSourceId`、`reverseSourceId`，在本地原子保存明确两面及必要的图片归属调整。其他未确认、未识别且未收藏的钱币可以移出所选照片，剩余照片仍留在原记录；已确认的其他钱币、已有业务结果及资料图片受保护。所有原件保留，版本冲突不覆盖。编辑时轮询仍读取任务，但不覆盖当前草稿；任务更新后需重新查看最新照片。保存后回到添加页下一步，只准备识别预览，不自动提交识别。

编辑器内补图通过原字节上传接口的 `mode=stage` 归档，仅更新编辑草稿，不触发自动整理或远端操作；最后由“保存并继续”提交。普通缺面卡片的直接补图继续沿用下述原子补图流程。

尚无识别结果时，待确认和缺面项展开；已有结果时，识别结果及收藏按钮置前，待确认和待补图折叠并保留数量及用户展开状态。展开缺面项即可在缺失的位置“补正面 / 补反面”。混合任务中的待识别组仍保留独立识别按钮。`POST /api/connector/photo?task=<key>&revision=<revision>&localId=<local-id>&side=obverse|reverse&name=<filename>` 只接收当前浏览器上传的一张图片字节流。后端校验当前版本、目标记录、缺失方向和图片唯一性，再通过任务包的一次归档事务保存来源、配对事件和原记录；不会重建候选、触发整批整理或调用远端识别。识别过或已收藏的记录不能从此入口换图。返回丢失时先读取该条记录，不自动重传。

识别成功的每枚钱币使用完整结果卡：原照片、国家/地区、面额、年份、材质、目录编号、造币标记、重量、直径、厚度、发行量、已返回的服务参考价和参考图直接展示，不再藏进“识别详情”。参考图明确标为非本枚实物，可点击放大；只显示允许来源的图片。未返回的资料显示“—”，不推断或补造币种与价格。批量结果逐枚展示，保留勾选和批量收藏。

后台整理期间可从同一入口继续批量上传。每份上传先原子归档并更新整理批次；旧分析输出不能覆盖新批次，后台随后自动整理最新资料。已确认、已识别和已收藏的记录继续受保护。单份文件保存中暂时禁用重复选择；仅明确返回 `409 revision_conflict` 且尚未接收该文件时，页面重读版本并重试一次。已有保存回执或结果未知时不自动重传。

所有数量的钱币都从 `#add` 办理：上传后自动整理，完整配对默认勾选，页面自动只读检查账户与识别资格。用户在本页确认“识别这 N 枚”；结果仍显示在本页，对照实物后确认“加入收藏”。缺面钱币直接显示补图入口，其他资料折叠展示。本次选定范围全部收到成功收藏回执及真实收藏关联后，自动进入“我的收藏”并显示成功数量；若原任务还有未处理钱币，保留“继续处理”入口。全部钱币已确认收藏、且无未决操作或待整理资料时，同时释放添加入口，再次添加显示空白上传区。未知、部分失败、或尚未读取收藏关联时不跳转。历史完成任务不重复触发成功跳转。完成的任务、原件和操作回执仍保留在历史记录中，已收藏钱币从“我的收藏”查看。任务仍有缺面钱币时，补充照片继续归入原任务；已识别和已收藏记录由整理器保护。

`POST /api/connector/identification-plan` 在原有冻结范围之外返回只读 `eligibility`；执行时继续复核资格、账户、版本、哈希和精确 localIds。连接失败不弹出技术错误对话框，不自动重复检查，更不自动发起识别；用户可在原页“重新检查连接”。HTTP 200 但非预期 JSON 仍视为服务不可用，保留 CLI 原始日志。

批量收藏使用 `POST /api/connector/collect-batch`：`taskKey`、`expectedRevision`、`commandId` 以及 `items:[{localId,snapshotId}]`，每次 1–500 枚且不重复。后端先整体核对每一份已展示快照和资料冲突，保存确认意图，再原子保存审核决定，通过原收藏计划与执行器办理；未知结果不重放。原单枚 `collect` 接口继续兼容。此流程不授权鉴定、追踪、购买或扩大所选范围。

## 本地准备与恢复

```bash
python3 <workspace>/scripts/connector.py prepare --obverse <正面绝对路径> --reverse <反面绝对路径>
python3 <workspace>/scripts/connector.py status --task-key <key>
```

`prepare` 自动归档原件、建立单枚候选并保存明确的正反面；不会上传到远端。重复处理同一任务时显式提供 `--task-key`，不要把另一对照片合进已识别对象。方向和归属必须来自本次用户资料及已确认判断，不能把任意两图当同一枚。名称可用 `--title` 指定，否则自动产生。

当前对话保存返回的 taskKey；用户说“继续”时先用它读取最新状态。没有当前对象时只澄清对象，不能选择全局最近任务。`--home` 仅用于明确的隔离测试或恢复目录。

## 展示范围，再开始识别

```bash
python3 <workspace>/scripts/connector.py identification-plan --task-key <key>
python3 <workspace>/scripts/connector.py identify --task-key <key> --revision <revision> --plan-hash <hash> --command-id <UUID> --confirmed
```

预览只读，返回当前照片范围及账户绑定。用户看到正反面、上传目的和服务实际给出的费用/额度后，确认才允许执行；未知费用或额度明确说明，不补造“免费”或剩余次数。账户、照片或 revision 变化时旧预览失效。已有同范围授权可以复用。

`--confirmed` 仅表达 Agent 已取得这一次精确动作的用户授权；工具参数本身不能代替真实授权。所有正式业务仍由 CLI 执行器进行。保留同一次意图的 commandId，未知结果先 status/核验，不能换新 ID 绕过。

## 核对结果后直接保存

```bash
python3 <workspace>/scripts/connector.py collect --task-key <key> --revision <revision> --local-id <localId> --snapshot-id <snapshotId> --command-id <UUID> --confirmed
```

先显示当前照片、可读识别结果和未解决差异。用户明确接受该结果并要求加入收藏后，这一个动作在内部保存采纳决定、生成原有收藏计划、绑定摘要并执行。snapshotId 必须是用户刚看过的成功识别；不接受陈旧结果、未识别记录或身份冲突。同一 commandId 不重放写入，不同对象不得复用 commandId。

`status` 返回真实持久状态；只有成功响应且具有真实收藏关联时才报告已收藏。运行中显示正在处理，明确失败保留原因，未知写入保持待核验。所有原有完整性、账户、版本、确认、审计和失败恢复规则继续生效。

## 可视辅助

```bash
python3 <workspace>/scripts/workspace.py start --no-default-browser --page add --task-key <key>
```

整理保存后需要用户核对时，按工作空间 Skill 的宿主规则主动打开或复用本次任务的 `add` 页。同一个资料区接收资料并归档，上传结束后本机服务自动运行已登录的 Codex 做资料整理及配对，状态通过任务事件同步到页面；页面展示同一任务的资料与进度，明确需要纠错时才进入对应步骤。返回 URL 含本机浏览器连接凭据，只能交给浏览器打开工具，不写进聊天或业务日志。

网页上传自动启动的整理 worker 独立于聊天 turn；失败可在原页面重试。可用 Codex CLI 和有效登录是该自动化的运行依赖，使用 Codex 额度。worker 为只读、临时会话，无 shell、MCP 或线上业务权限，只输出受约束 JSON；来源与版本验证通过后由后端正式落盘。普通聊天仍是当前宿主的直接续办入口，不需要用户选择宿主、发送 inbox 提示语或保持轮询。旧网页交办仍为 pull 模式，不宣称能原生唤醒停止的 Agent。

## 页面进度与反馈

添加页工作中显示上传、整理、识别、收藏四个阶段；完成后缩为一行真实数量摘要，把主要区域交还识别结果。上传按已保存回执显示完成份数；整理仅使用 `organization.stage` 展示读取资料、匹配正反面、保存结果，不推算逐图百分比。识别和收藏按本次操作的去重 scope 与 itemResults 统计成功枚数，重试保留的失败结果不计为成功；未知结果静态提示待确认，等待用户确认与正在工作使用不同状态。

进行中展示旋转指示、真实数量进度或不定进度；相同轮询结果不重建添加页，避免动画重播、展开项关闭。按钮与上传区域提供轻反馈，成功跳转时显示一次短过渡，并遵循减少动态效果设置。
