# HeriBase 识别结果分组与排序

在识别审核阶段使用本参考。结论必须能回溯到服务端返回的标题、年份、铸记、估值、证据、置信度，或本地资料的图像质量与配对置信度；不能编造稀有度、市场价格、专家意见或评分。

## 每项审核信息

每个已识别候选项展示：

- 永久 `local_id`、标题、年份、铸记和 `identify_uri`；
- 服务端已返回时展示 `user_uniq_uri`，并保持与 raw 响应的追溯关系；
- 服务端实际返回的估值、证据和置信度；
- 本地配对置信度、图片质量警告和疑似重复关系；
- 是否已收藏（仅在 CLI/API 已返回此信息时）；
- 推荐动作及其明确理由。

## 三组结果

| 分组 | 进入条件 | 默认建议 |
|---|---|---|
| 值得收藏/关注 | 证据支持的较高估值、稀少年份或版别信号，或值得持续追踪的特征；且识别与配对没有重大不确定性 | 推荐加入收藏；必要时建议继续研究或追踪 |
| 需要补图或复核 | 缺少正反面、低置信识别、证据不足、图片模糊、识别失败或疑似重复 | 不建议直接收藏；说明需要的补图或复核动作 |
| 普通硬币 | 结果明确，且没有已有证据支持的特殊关注信号 | 可加入收藏，或仅保存识别报告 |

“普通”不表示绝对低价值，只表示当前识别和证据中没有足以优先处理的信号。

## 可解释排序

先按是否需要复核分离，再在“值得收藏/关注”和“普通硬币”组内排序。排序依据按优先级使用：

1. 服务端提供且可比较的估值、稀少性或关键版别信号；
2. 服务端提供的证据和置信度；
3. 用户明确说明的关注目标，例如特定国家、年代或系列；
4. 本地配对与图像质量警告，用于降低推荐确定性，而不是制造新的价值判断。

若没有可比较的估值或稀少性数据，只按用户目标、证据完整性和置信度排序，并写明“缺少可比较的市场/稀少性数据，未按价值排名”。

推荐理由应保持简短、可追溯，例如：“推荐关注：服务端识别为 1916 年版，估值摘要高于本批其他可比较结果，正反面证据完整。”
