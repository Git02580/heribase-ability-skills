# 全量图片配对方法

用于散图、表格图片和评级盒照片的本地候选整理。目标是提高“值得用户复核的可能配对”召回率，同时保持自动确认的准确度；配对建议不是正式决定。

## 处理顺序

1. **盘点全量来源。** 记录每张图片的 `source_id`、原始文件名、像素尺寸、来源位置及当前活动记录归属。图片原件已归档后，尽力读取本地尺寸与 EXIF 元数据，再读取全量缩略图建立整体印象、逐张打开原图核对细节；缩略图不能作为方向、年份或细字的唯一依据。EXIF 不存在、被清除或无法读取时继续视觉配对，不得因此中止。表格同一行的正反面 URL 是直接关联线索，只有两张图片均成功归档后才作为视觉证据。
2. **逐图识别可见属性。** 尽量记录币种/发行者、面额、可见年份与铸记、图案或人物、文字、孔洞/切边、双金属结构、直径比例、边缘形态和拍摄背景。无法辨认的字段留空。先判断正面、反面、评级盒、标签、细节图或未知；看不准方向时不要猜。
3. **建立全局候选表。** 对所有未确认来源进行两两比较，不能只比较相邻文件、第一眼相似图片或当前选中记录。将可见币种/版别兼容性、唯一背景/环境线索、来源关联与 EXIF 元数据用于候选召回和排序，再回看原图确认；不得将这些线索误当成已配对事实。每张未配对图片保留最多 3 个排名靠前且有证据的候选，确保还有合理候选时不会直接遗失在单图列表里。完整记录明显冲突项，避免重复试配。
4. **全局消除冲突。** 同一张图片不得同时分给多个活动候选。按整批证据统一选择互不冲突的组合；若最佳方案依赖主观判断或候选分差很小，将竞争组合都留给用户审核，不用贪心顺序锁死早期选择。
5. **形成候选记录。** 对有依据但未获用户确认的配对，建立包含相关来源的 `active` 候选，设为 `pairing_state: needs_review`；在 `organization.pairing_suggestions` 中保存候选证据。单张来源也保留其最相关的候选建议。只有表格行明确提供且两张图均成功归档的正反面可标记 `table_row_complete`。其他配对不能预填人工确认状态。

## 比较依据

正反面图案通常不同，因此不要求图案相同。综合以下信号，注明实际看到的内容，并区分独立证据类别；同一拍摄条件产生的多项 EXIF 字段不能虚增为多项强证据：

- **强支持：** 同一表格行的正反面来源；硬币直径/边缘/双金属结构等实物特征一致；发行者、面额、币种和年份组合相符；背面文字与正面可见信息互相支持；评级盒认证号、机构、等级或条码一致。若某一种币种、年份或版别在整批照片中确实唯一，另一张图的对应面与该发行信息兼容，可显著提升候选排名；但“该版别唯一”仍不等同于已证明是同一枚，须继续比对实物状态、边缘、细节和来源。
- **辅助支持：** 相似的拍摄尺度、光线和背景；同组照片的文件命名或采集顺序；经核实在当前任务内较少见的背景/环境特征。独特背景可以提示同一拍摄场景或同组资料，不能证明硬币相同；普通桌面、灯光或颜色一致是弱线索。相机品牌与机型、像素尺寸相同、EXIF 拍摄时间接近或 GPS 位置接近也只作辅助信号：品牌和机型合并算一个“设备”类别，同一台设备连续拍摄多枚不同硬币很常见。
- **EXIF 候选召回：** 完整归档图片后运行 `python3 <skill-dir>/scripts/analyze_image_metadata.py --task-key <task_key>`。工具只在本机读取图片，默认以 15 分钟、100 米作为“接近”的可调候选阈值；比较时间接近、GPS 距离接近、像素尺寸完全一致，以及相机品牌/机型是否一致。至少两类元数据吻合且包含时间或位置接近，或至少三类元数据吻合，才列入元数据候选。品牌和机型是同一类别；GPS 与时间只表示可能同场拍摄。读取报告 `derived/image-metadata-analysis.json`，把它与币面视觉比较结合后，再将真实候选及证据写入 `organization.pairing_suggestions`。若当前 Python 环境缺少 Pillow，脚本会主动尝试用 `sys.executable -m pip install Pillow` 安装；成功后继续，失败时将原因写入报告并跳过可选元数据步骤，正常配对照常进行。若 Pillow 已安装但照片不含 EXIF，不能靠安装软件恢复照片里不存在的信息；仍使用像素尺寸并继续视觉配对。GPS 无效、单张图片损坏或 EXIF 不可读只影响相应元数据线索，不应阻断整批。
- **冲突：** 尺寸和边缘特征明显不兼容、币种/发行者/面额互相排斥、可见年份或标记冲突、两图其实是同一面重复照片，或候选已被其他记录占用。区分“同一枚的反面”“同一面的重复照片”“细节图”和“不能判断”。

颜色相近、背景相同、尺寸看起来接近、设备品牌/机型相同、EXIF 时间或位置相近、人物相似或都属于同一国家/年份都不足以单独配对。脚本只要求像素尺寸完全相同才计入该字段。评级标签是来源声明，不能覆盖币面直接证据。

### EXIF 隐私与解释边界

脚本报告会保存来源 ID、像素尺寸、相机品牌/机型、元数据是否存在，以及来源对之间的“接近”信号；GPS 坐标和精确拍摄时间只在内存中计算，不落盘、不写入 item、不放进聊天或工作台展示。不会提取或保存设备序列号。不要把坐标、原始 EXIF 或推测出的拍摄地址复制到 `rationale`。EXIF 字段可能缺失、被编辑软件改写或不准确；相机时钟/时区可能偏移，GPS 精度也可能很低，因此这些信息仅是召回线索，不是同币证据。

## 持久化格式

把建议写入各相关 item 的 `organization.pairing_suggestions`，同一对来源在两端记录一致的建议。按置信度降序排列；置信度是模型估计值，不是校准后的统计概率。只引用当前任务中存在的 `source_id`。

```json
{
  "source_ids": ["source-front", "source-reverse"],
  "relation": "opposite_faces",
  "confidence": 0.78,
  "rationale": "两图双金属结构与外圈宽度相符；币面文字分别呈现同一币种的发行者与面额。",
  "supporting_signals": ["相同双金属结构", "币种文字相符"],
  "conflicting_signals": []
}
```

`relation` 取值为 `opposite_faces`、`same_face_duplicate`、`same_coin_detail` 或 `uncertain`。数组最多保留 3 项。审核台显示两张来源的原图、关系、模型置信度、支持点和冲突点。建议只用于比较和用户审核，不能写入 `source_assignment`、不能自动触发识别，也不能代替用户决定。

## 置信度与升级

- **高（≥ 0.85）：** 至少有两个互相独立的强支持信号，且没有未解决的冲突。进入自动就绪候选，但仍受整理任务的首次确认约束。
- **中（0.60–0.84）：** 有明确候选依据但仍存在替代解释。建立待人工确认候选并展示竞争候选。
- **低（< 0.60）或方向未知：** 不自动归组；保留有证据的首选建议供用户查阅，并把其余来源作为待整理单图。

如果原图太小、模糊或遮挡，或关键候选判断需要补充图片，明确列出缺失证据并请求用户补图。不要因模型名称或推理等级猜测已检查过所有组合；无法完整查看时说明实际比较范围。
