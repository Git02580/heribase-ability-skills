# 盒子币标签分析

在输入包含 PCGS、NGC 或其他评级盒照片时使用本参考。目标是从可见标签提取可追溯的定位线索，不能以模型输出替代服务端身份或用户决定。

## 候选与证据

- 一张同时包含硬币和标签的图像是 `graded_slab` 候选，可用 `slab` / `label` 证据角色表达标签面。
- 两张盒子图像仍做正反面配对；认证编号、评级机构、等级和条码匹配是强线索。只有币名、年份、等级或相似排版不构成充分配对依据。
- 标签图与裸币图冲突时，不覆盖任何一方；保留两组声明和冲突原因。

## 多模态输出字段

将分析写入 `field_claims.slab_label_analysis`。每条声明含 `source_id`、分析方法/模型标识、时间、总体置信度，以及逐字段的 `raw_value`、`normalized_value`、`confidence`、`evidence_region`。可识别字段：

| 字段 | 用途 |
|---|---|
| `grading_service` | PCGS、NGC 等评级机构 |
| `certification_number` | 封装认证编号；必须逐字符可见 |
| `grade` / `designation` | 等级及 RD、BN、CAM 等附加标记 |
| `coin_title`、`year`、`mint_mark`、`denomination` | 盒标上的币种定位信息 |
| `km_number` | 可见的 Krause 编号，仅作为检索线索 |
| `barcode`、`other_attributes` | 可见条码或其他盒标属性 |

不得根据校验位、常见格式、目录习惯或相邻字符补齐编号；不确定值置 `null` 并添加 `label_needs_review`。

## 审核路由

- 散图和表格均自动就绪时：若存在盒子币，询问用户是否审核标签结果；用户选择跳过时，仅将高置信、完整证据的标签线索列入首次识别确认卡。
- 任一散图或表格项需要配对核对时，在本次任务的 `add` 页查看配对。页面未展示的盒子币标签字段、置信度、原始证据和冲突或缺失状态，由 Agent 在当前对话中补充，并把确认结果加入同一任务的确认范围。
- 标签字段不能直接调用后端；首次识别确认仍需展示准确范围、数据集版本和“将上传/查询”的外部影响。
