# HeriBase 收藏任务协议

本参考定义用户可见的任务卡和确认卡。对用户描述任务本身，不提及 Skill、内部阶段或 API。

## 六阶段任务卡

| 阶段 | 必须展示 | Agent 可以做什么 |
|---|---|---|
| 意图 | 已理解的目标、资料范围；仅在影响范围不清时澄清 | 读取用户提供的本地资料 |
| 计划 | `task_key`、输入数量、将执行的步骤、预计耗时（若可判断）、已知或未知的额度/费用、不会执行的动作 | 创建/恢复自包含任务包并建立本地整理快照 |
| 分析 | 当前阶段、已处理/总数、异常和已完成项 | 配对、去重；首次确认后上传与识别 |
| 审核 | 结果分组、证据、置信度、推荐和下一步 | 生成本地收藏草稿 |
| 确认 | 精确对象、数量、费用/额度、外部影响和未处理项 | 等待明确确认 |
| 执行 | 成功、部分成功、失败、可重试范围及其原因 | 调用已确认的原子 CLI 命令 |

没有可靠来源时，用“当前未知”表示费用、额度、权益或耗时；不得把“可能适用”变成具体数字。

## 首次确认：进入识别

首次确认只授权任务包中列明的记录进入上传和识别。此时未创建收藏、不写收藏，也没有服务端确认令牌。确认必须记录用户看到的 dataset revision、item version 与数据集指纹。

确认卡至少应包含：

| 内容 | 说明 |
|---|---|
| 输入摘要 | 图片数、目录、XLSX 行数、资料来源 |
| 表格处理摘要 | 总行数、去重后的表格候选数、正反面图片下载成功数、下载失败行及仅字段候选数 |
| 盒子币摘要 | 单图/正反面盒子币数量、可读 PCGS/NGC 认证编号数、KM 线索数及待复核标签数 |
| 候选结论 | 候选实物数、高/中/低置信配对、单面、重复和无法归类数 |
| 候选明细 | 永久 `local_id`、正反面/评级盒关联和任务包来源 |
| 识别范围 | 明确哪些候选项会上传并识别；哪些会留待补图或复核 |
| 外部影响 | 确认后图片将上传到 HeriBase；已知或未知的额度/费用 |

示例：

```text
整理结果待确认

- 已发现：48 张图片、1 个 XLSX（36 行）
- 候选实物：26 枚；高置信配对 21 枚
- 待补图或复核：4 枚；疑似重复：1 组
- 确认后将上传并识别：20260828-1034-batch-flat:local-01 … local-21（共 21 枚）
- 不会处理：4 个待补图项及 1 组疑似重复项
- 识别额度/费用：当前未知

确认上述配对和识别范围吗？
```

只有用户明确确认具体候选项后，才将其置为 `identification_pending`。若用户取消，保留草稿或结束会话，不上传、不识别、不写收藏。

## 配对确认：识别前门槛

配对确认发生在首次识别确认之前，适用于散图候选以及已成功归档图片的表格候选。任一候选配对置信度低于 `0.85`、缺正反任一面、证据重复引用、来源字段冲突或显式标记待确认时，按收藏 Skill 的规则主动打开绑定本次任务的工作台 `add` 页。

- 核对时展示正反面证据、来源类型、表格工作表/行/列、原始 URL、下载状态与冲突提示。图片使用已归档的任务证据。`add` 未展示的必要细节由 Agent 在当前对话中补充。
- 盒子币候选展示标签原图、评级机构、认证编号、等级、附加标记、币名/年份/铸厂/面额、KM 编号、条码及逐字段置信度。它们是多模态来源声明，不是服务端事实。
- `add` 支持查看配对、调整正反面和补图。需要拆分、合并、批量确认、标记待补图或排除时，页面没有相应操作的部分在当前对话中办理。批量只处理确认配对、标记待补图和排除，先展示影响范围和跳过项，由用户确认后逐项记录并共享 `batchActionId`。批量确认要求已有方向明确的正反面证据，拆分、合并与调整方向逐条处理。页面保存后读取最新任务状态；对话中取得的决定由 Agent 通过 `import-pairing` 校验并保存。
- 盒子正反面优先按可见认证编号、机构、等级或条码辅助配对；仅同年份、币名或相近等级不能自动配对。盒标与裸币图冲突时必须显示冲突而非覆盖。
- 没有成功归档图片的表格行仅能作为字段候选和异常展示，默认不得配对通过或进入识别；图片补齐后刷新本次任务的 `add` 页继续核对。
- 全部候选高置信且没有表格下载/关联异常时，若没有盒子币可跳过交互页面；若有盒子币，先询问用户是否要审核标签提取结果。用户选择跳过时，首次确认卡仍须列出自动配对数量、盒标检索线索、待复核字段和被排除的异常项。

## 分析进度

识别时用可核对的进度汇报，例如“正在识别 7/21；已成功 5，失败 1，等待处理 15”。不得把上传成功说成识别或收藏成功。详情见 [失败、取消与恢复](recovery-and-confirmation.md)。

## 第二次确认：加入收藏

第二次确认只发生在识别审核之后，并由 `collection/plan.json` 表达精确范围。确认卡至少包含：

| 内容 | 说明 |
|---|---|
| 待写入条目 | `local_id`、识别标题、`identify_uri`、`user_uniq_uri`（若已返回），精确数量 |
| 不写入项 | 低置信、待补图、疑似重复、识别失败和用户排除项 |
| 影响 | 仅新增哪些收藏；不会送鉴、上架或修改未列出的资产 |
| 成本 | CLI/API 返回的费用或额度；未知时明确标记 |
| 确认绑定 | 当前 dataset revision、数据集指纹与 plan payload 摘要 |

示例：

```text
加入收藏前确认

- 将新增收藏：12 条（已列出的候选项）
- 将保留为识别报告：7 条普通硬币
- 不会写入：2 条低置信结果、1 条识别失败项
- 影响：仅创建上述收藏记录；不会送鉴、上架或修改其他资产
- 额度/费用：当前未知

确认将所列 12 条加入收藏吗？
```

仅在用户明确确认当前计划摘要，并在执行前复核摘要未变化后，逐条执行 `heribase collection add --uri <identify-uri> --json`。用户选择“只保存识别结果”时，不执行收藏写入。任何图片证据、身份、决定、item version 或范围变化都会使计划过期，必须重新生成并确认。

## 审核台决定协议

- 单项和“本分组全选”都要逐条产生审核事件；批量事件共享 `batch_action_id`。
- 审核台从任务包的 `derived/review-dataset.json` 读取展示数据，通过受限本地服务或 JSON 导入写回；`localStorage` 只用于临时 UI 恢复。
- 用户决定为 `collect`、`need_photo` 或 `exclude`；Agent 推荐另存，不可冒充用户决定。
- 页面重开后，以 `review/decisions.jsonl` 重放结果；若用户审核后基础数据已改变，明确显示“决定已过期”。
